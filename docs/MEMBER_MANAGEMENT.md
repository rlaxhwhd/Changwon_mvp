# 최고관리자 회원관리

- 조교학과배정: `/admin/members/assistants`
- 교수학과배정: `/admin/members/professors`
- 기업회원관리: `/admin/members/companies`
- 이전 `/admin/members/assignments`, `/admin/members/academic`는 조교학과배정으로 이동한다.

## 학과 배정

대학·학과·전공 코드는 학사 복제본의 조직 계층을 사용한다. 학과별 복수 인원을 지원하며,
이름·사번 검색은 재직 조교/교수와 기존 로컬 교직원을 역할별로 조회한다. 연락처는
원본 `hp`·`tel`을 사용하며 없는 값은 빈 연락처로 표시한다. 원본 코드의 접두어와 앞자리 0을 보존한다.

`071`은 별도 운영 테이블 `dc.department_staff_assignment`와 제한된 조회 뷰를 만든다.
기존 활성 `dc.org_assignment` 및 코드가 일치하는 원본 조교 배정을 연결한다.
`073`에서 교수 소속을 초기 배정으로 반영했던 동작은 `074`에서 정정한다.
학사DB의 교수 소속은 상담 배정이 아니다. 교수는 검색 후보로 제공하고, 관리자가
상담을 맡길 학과·전공에 명시적으로 등록한다. 같은 교수를 여러 전공에 등록할 수 있다.
빈 배정 칸은 소속 교수가 없다는 의미가 아니라 별도 상담 배정이 없다는 의미다.
`074`는 073 적용 시각에 생성된, 관리자 변경 이력이 없는 자동 교수 배정만 비활성화한다.
삭제하지 않고 `source=academic_professor_retired`로 보존하며 재활성화는 금지한다.
기존 운영 배정과 관리자 등록, 조교 배정은 유지한다. 학사 복제로 상담 배정을 자동 생성하지 않는다.

관리 API `/api/v1/system/department-assignments`는 최고관리자 권한을 검사한다.
`/candidates`는 이름/사번 검색, POST는 등록, `/{id}/release`는 버전 확인 후 해제다.
등록·해제는 감사 이력을 남긴다. 기존 배정 해제는 연결된 `org_assignment`도 종료한다.
로그인 계정이 있는 교직원에게만 담당 학생 범위가 적용되며, 전공 배정은 해당 전공 학생으로 제한된다.
명시적인 '학과 전체' 배정과 기존 지도교수 배정 등은 각 기존 범위를 유지한다.
자동 교수 배정의 비활성화는 그 배정에서 생긴 학생 접근 범위도 제거한다.
원본에 인원이 있다는 이유만으로 교직원 로그인 계정을 생성하지 않는다.

## 기업회원 가입 승인

1. `/login`의 기업회원 탭에서 `/company/register`로 이동한다.
2. 회사명, 사업자등록번호, 비밀번호, 담당자 이름·이메일·연락처를 입력해 가입을 신청한다.
3. 최고관리자가 기업회원관리의 승인 대기 목록에서 신청을 검토해 승인하거나 사유와 함께 반려한다.
4. 승인된 기업은 사업자등록번호와 신청 시 비밀번호로 로그인하여 `/company`에서 회원 정보를 확인한다.

사업자등록번호는 하이픈을 제거한 10자리로 유일성을 보장한다. 관리자 검토를 거치며
외부 사업자 진위조회 서비스에는 연결하지 않는다. 비밀번호는 10~128자이고 개별 salt를 사용한
scrypt 해시로 저장한다. API 응답·감사 이력에는 비밀번호와 해시를 넣지 않는다.

`072`는 `company_member`, `company_login_session`, `company_auth_rate`를 추가한다.
승인 전에는 세션을 발급하지 않으며, 승인 시에만 채용 기업 정보 `dc.company`를 생성·연결한다.
회원 세션은 학생·교직원 인증과 분리된 HttpOnly/SameSite 쿠키로 유지하며 8시간 후 만료된다.
로그인/가입 요청은 서버 측 요청 횟수를 제한한다. 운영 환경에서는 HTTPS를 사용한다.

공개 API: `/api/v1/auth/company/register`, `/login`, `/me`, `/logout`.
관리 API: `/api/v1/system/company-members`, `/{id}/review`.
처리된 신청 재승인·재반려는 409로 거부하며, 반려에는 사유가 필요하다.
기업용 공고 작성, 비밀번호 재설정, 반려 후 재신청 및 이메일 알림은 이번 기능에 포함하지 않는다.

## 적용 및 검증

071 → 072 → 073 → 074 순서로 마이그레이션 적용 후 API 서버를 재시작한다.
로컬 `dreamcatch`와 `dreamcatch_test`에는 네 마이그레이션을 적용했다.
기존 062 체크섬 불일치로 전체 마이그레이션 실행이 막혀, 기존 파일이나 기록을 바꾸지 않고
새 마이그레이션만 소유자 연결의 트랜잭션·마이그레이션 잠금 안에서 적용했다.

신규 테스트는 `test_department_assignments.py`, `test_company_members.py`에 있다.
기존 학생 로그인 테스트는 현재 테스트 DB의 `fixture_student_login_source` 누락 등
학사 로그인 테스트 데이터 준비가 필요하다.
