# 심리상담센터 연계

2026-09-14 구현. 관리자 상담 관리의 `/admin/counsel/psych-referrals`에서 진로취업상담사가 학생을 심리상담사에게 연계한다. 기존 admin 페이지의 공통 카드·폼·상태 배지·색상 토큰을 사용한다.

## 업무 흐름

1. 진로취업상담사가 담당 범위의 학생을 이름·학번으로 검색한다.
2. 학생, 담당 심리상담사, 드롭다운 사유를 선택해 전송한다. 자유 텍스트 사유는 UI와 API 모두 허용하지 않는다.
3. 지정된 심리상담사의 받은 연계에 표시되고 사이트 알림이 생성된다.
4. 심리상담사는 `접수 대기 → 처리 중 → 처리 완료`로 진행한다. 보낸 상담사에게 접수·완료 알림이 전달된다.
5. 보낸 상담사는 접수 대기 상태에서만 취소할 수 있다. 취소 시 받은 상담사에게 알림을 보낸다.

사유는 DB의 5개 항목이다: 정서적 어려움 / 대인관계 어려움 / 대학생활 적응 어려움 / 스트레스·생활관리 어려움 / 심리검사·전문상담 필요. 상담 필요 영역이며 진단명이나 CARE 7+ 판정이 아니다.

연계는 별도 인계 업무다. 기존 진로취업 상담을 심리상담으로 바꾸거나 삭제하지 않으며, 예약·상담일지·진단 결과를 자동 생성하지 않는다. 처리 완료는 담당자의 연계 처리 완료 표시이며 상담 수료나 치료 결과를 의미하지 않는다. 상세 심리상담 기록은 기존 심리상담 기능에서 관리한다.

## DB와 API

마이그레이션 `067_psych_referral.sql`:

- `dc.psych_referral_reason`: 사유 코드·라벨·순서·활성 여부.
- `dc.psych_referral`: 학생, 발신·수신 담당자, 사유, 상태, 버전, 연계·접수·완료·취소 시각.
- `dc.psych_referral_event`: 생성·접수·완료·취소의 변경 불가 이력.
- `dc.menu` / `dc.menu_auth`: `counsel.7`, career·psych에게 메뉴 제공. 프런트 메뉴의 기존 순서는 유지한다.

API는 `/api/v1` 아래에 있다.

| 경로 | 용도 |
|---|---|
| `GET /psych-referrals/options` | 역할, DB 사유 목록, 심리상담사 목록 |
| `GET /psych-referrals/students?q=` | 발신자 범위의 학생 검색, 최대 30명 |
| `GET /psych-referrals?page=&status=` | 본인 발신/수신 목록, 20건 페이지, 상태별 전체 집계 |
| `POST /psych-referrals` | 학생·심리상담사·사유 코드로 신규 연계 |
| `POST /psych-referrals/{id}/transition` | `action`과 기대 `version`으로 상태 전이 |

화면은 진입·포커스 복귀·30초 간격(보이는 탭) 및 수동 새로고침으로 목록을 조회한다. 빈 목록과 조회 오류를 구분하고, 전송 중 중복 클릭을 차단한다.

## 권한·일관성

- API에서 staff 역할과 `counsel.7` 메뉴 권한을 확인한다. 일반 시스템 관리자·교수·학생에게 허용하지 않는다.
- career는 본인이 보낸 연계만, psych는 본인에게 배정된 연계만 조회한다. 추측한 타인 연계 ID의 변경은 404다.
- 발신 학생은 기존 `student_access`와 같은 담당 범위 또는 실제 상담 배정 관계가 있어야 한다. 수신자에게 학생 전체 프로필·다른 상담·CARE 데이터에 대한 새 권한을 부여하지 않는다. 받은 연계에서 기본 학생 식별정보와 연계 사유를 확인할 수 있다.
- 학생당 진행 중 연계는 하나다. 학생별 트랜잭션 잠금과 부분 unique 인덱스로 중복 요청을 막는다. 종료 후 새 연계는 가능하다.
- 상태 변경은 행 잠금·기대 버전 확인을 사용한다. 상태, 이력, 사이트 알림은 같은 트랜잭션으로 반영한다.
- 알림은 기존 `dc.notification`을 사용한다. 학생 이름·연계 사유를 알림 본문에 복사하지 않는다. 외부 이메일·SMS 발송은 없다.

## 검증·적용

- API 회귀 테스트 10개: 전체 흐름, 알림·변경 불가 이력, 중복 방지, 잘못된 상태 전이, 접수 후 취소 방지, 역할·수신자·학생 범위, 유효 사유·심리상담사, 자유 텍스트 거부, 필터·페이지 검증.
- 프런트 빌드·변경 파일 ESLint 통과.
- 실제 브라우저에서 진로상담사 검색·5개 사유·전송, 심리상담사 접수·완료, 발신 목록 새로고침을 확인했다. 브라우저 오류 0. 화면도 두 역할에서 확인했다.
- API 테스트는 격리 DB에서 쓰기 후 롤백한다. 브라우저 검증의 연계 생성·처리도 `dreamcatch_dashboard_20260914_test`에서만 수행했다.
- 로컬 `dreamcatch`에 067 적용. 적용 전 백업은 Git 제외 `_workspace/backups/dreamcatch-before-psych-referral.dump`. Oracle 변경 없음. 프런트·API·마이그레이션을 함께 배포한다.
