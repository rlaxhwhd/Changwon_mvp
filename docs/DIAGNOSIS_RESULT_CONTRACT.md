## 저장과 표시

- 정의: `dc.diagnosis_factor_definition`, 표시명: `dc.code_item`의 `DIAGNOSIS_FACTOR` 그룹. 관리자 `/admin/system`에서 기존 표시명을 수정할 수 있다. 항목 코드의 추가·변경은 검사 정의 변경이므로 배포로 관리한다.
- 결과: `dc.diagnosis_result`, 응시: `dc.diagnosis_attempt`. 결과의 `factors`는 `factorCode`, 응시 당시 `name`, `tScore`, 선택적인 `level`을 사용한다. 값이 없는 항목은 0점으로 만들지 않고 미등록으로 표시한다.
- C2·C3·C4 수준은 제공된 `level`을 표시한다. 이번 예시만으로 낮음·보통·높음 경계값이나 채점식을 확정하지 않는다.
- 기존 JSON 결과 원본은 DB에 보존한다. 기존 요인과 새 요인의 대응이 확인되지 않은 점수는 이름 유사성이나 배열 순서로 매핑하지 않는다.
- `PRECOMPUTED`는 응시 전 준비한 예시 결과다. 실제 완료 이력 및 학생 결과 조회에서 제외한다.
- `/development/diagnosis/{test_id}/complete`는 SSH 개발 환경의 검증용 기능이다. 시드 fixture 가 있는 학생은 그 결과를 쓰고 `source=development:fixture`를 남긴다. fixture 가 없는 학생(학사 미러 실학생)은 결과표 항목(C2~C4 는 `diagnosis_factor_definition`, CCORE·C1 은 fixture 요인명)에 T점수 30~70 임의값을 채우고 `source=development:random`을 남긴다 — C-CORE 유형은 후속진단 결과표가 있는 T1~T4 중 무작위(이미 유형이 있으면 유지). 채점·판정 엔진이 아니며 외부 진단 결과를 API 로 받으면 대체된다(2026-09-17). 실제 검사·채점으로 표시하지 않는다. C5·C6는 이 기능으로도 생성하지 않는다.
- C2·C3·C4 예시 결과가 현재 항목에 대응하지 않으면 개발 테스트 기록도 거부한다. 점수표 항목 추가만으로 진단 완료 상태를 만들지 않는다.
- 학생 화면의 완료 판정은 DB의 응시 이력으로만 결정한다. 유형 존재 및 모듈의 공통 `recentAt`으로 완료를 추정하지 않는다.
- 검사 현황·요약·코멘트·권유는 `/api/v1/diagnosis/*`를 사용한다. 코멘트와 권유는 append-only이며 외부 SMS/메일 전송은 하지 않는다.

## 외부 진단 결과 그래프 (2026-10-07 확정)

- 학생 외부 진단 결과 페이지는 왼쪽 그래프·오른쪽 압축 결과표로 표시한다. 좁은 화면에서는 그래프와 표를 위아래로 배치한다.
- C-Core는 다음 5개 쌍의 T점수 산술평균을 축으로 하는 오각형이다: 진로명확성/진로동기, 역량준비도/취업역량준비도, 직무적합성/조직적합성, 정보탐색 및 분석/개인 브랜딩, 면접역량/구직전략.
- 평균은 화면 그래프와 접힌 요약표용이다. 원래 10개 점수·수준·유형·저장값은 변경하지 않는다. 쌍의 두 점수 중 하나라도 없으면 그 축과 평균을 비우며, 한 점수만으로 평균을 대신하지 않는다. 요약 수준은 아래 2026-10-08 기준을 적용한다.
- C-Core 요인 매칭은 HRTest 고정 코드를 사용한다. 응답 배열 순서나 이름 유사성으로 묶지 않는다.
- C-2는 API의 CLT(진로 학습 유형, 3축), COT(진로목표 지향성, 3축), CDT(진로 의사결정 유형, 4축)를 각각 그래프와 결과표로 표시한다. 유형은 `learning_type`, `goal_orientation`, `decision_type`의 제공값을 표시한다. 진로탐색행동·진로설계 수준의 나머지 점수는 아래 결과표에 유지한다(사용자 추가 확정).
- C-3는 D(진로명확성·진로동기), E(교내·대면·온라인·산업 네트워킹), F1(분석적 사고력·창의적 사고력·실행력), F2(관계유연성·협업지향성), T(직무·조직적합성) 하위 요인별 산술평균 5축이다. API 고정 척도 코드로 매칭하며 종합 영역 점수를 평균에 중복 포함하지 않는다. 필요한 하위 점수가 하나라도 없으면 해당 축을 비운다.
- C-4는 API의 R/E/A/D 영역 점수 4개를 축으로 표시한다. 미제공 점수는 0으로 바꾸지 않는다.
- 외부 진단 결과는 그래프 축의 점수와 영역 점수만 기본 표시한다. C-Core도 진로 / 준비도 / 적합성 / 브랜딩·네트워크 / 취업전략 5개 영역 평균을 기본 표시하고 10개 하위 유형은 접는다(추가 사용자 확정). C-2는 3개 유형 그래프의 10개 축 점수와 추가 영역 점수 2개를 유지하고 하위 15항목을 접는다. C-3는 영역 5개를 유지하고 하위 13항목, C-4는 영역 4개를 유지하고 하위 16항목을 접는다.
- 점수 표 우측 상단의 `하위항목 상세보기`를 누르면 같은 표가 `영역 | 유형 | 수준 | T점수` 형식으로 전환된다. 영역 셀은 소속 유형 수만큼 병합하고 영역 점수도 함께 표시한다. C-Core는 확정된 쌍의 코드, 나머지는 API `area`/`group` 코드로 묶는다. 소속 정보 없는 하위 점수도 `영역 미분류`로 보존한다. `상세 접기`로 요약표를 복원하며 새 결과는 접힌 상태로 시작한다. 펼침 동작은 추가 API 호출이나 점수 변경을 하지 않는다. 교직원 공용 결과표는 전체 항목 표시를 유지한다.
- 그래프·결과표 강조색과 배경은 진단 목록 카드의 `--diagnosis-1`~`--diagnosis-4` 및 `-soft` 토큰을 공유한다. C-Core 상단 축 이름은 100 눈금과 간격을 둔다.
- 그래프의 보통 표시 범위는 0~100이고 평균 50 기준선을 표시한다. 100을 T점수 만점으로 취급하지 않으며 범위를 벗어난 값은 축 범위를 확장해 표시한다.

## DB 우선 조회·회차 이력·요약 수준 (2026-10-08)

- 학생 결과 페이지 진입 시 `POST /diagnosis/external/{test_id}/import?preferStored=true`로 본인의 저장 결과를 먼저 확인한다. 실제 외부 결과(DONE/REVIEW)가 있으면 외부 API를 호출하지 않고 DB 이력을 조회한다. 개발 예시·미완료 기록만 있으면 외부 API 조회 후 기존 저장 경로로 적재한다. 이력 조회 권한은 기존 본인/교직원 접근 검증을 유지한다.
- 결과 페이지의 `진단 이력`에서 회차와 실시일을 선택한다. `새 응시 결과 확인`은 저장값 유무와 관계없이 외부 API를 조회한다. 새 결과가 없거나 조회가 실패해도 기존 결과는 유지한다. 이 기능은 재응시 승인 기능을 대신하지 않는다.
- DB는 이미 회차를 지원하므로 중복 테이블이나 새 마이그레이션을 추가하지 않는다. `diagnosis_attempt`와 `diagnosis_result`는 학생·검사·회차 복합 키로 연결되고, `diagnosis_factor_score`도 같은 회차별 점수를 보존한다. `hrtest_result`의 검사·외부 응시 ID 고유 키로 같은 응시의 중복 회차 생성을 방지한다. 새 외부 응시는 다음 회차로 추가하며, 같은 응시의 수정 결과는 그 회차를 갱신하고 `hrtest_result_revision`에 수신 버전을 보존한다. 회차는 기존 부여 번호를 유지하며 최신 결과는 검사 완료 시각으로 선정한다.
- 학생의 접힌 요약표 수준은 40점 이하 `낮음`, 40점 초과~60점 이하 `보통`, 60점 초과 `높음`으로 표시한다. 소수점은 반올림하지 않고 판정하며 점수가 없으면 `미등록`이다. 상세 하위항목 및 교직원 화면의 검사기관 제공 수준은 보존한다. 이 지시는 이전의 “영역 평균 수준 미판정” 표시 규칙을 대체하며 원본 DB 점수·수준을 변경하지 않는다.

## 남은 업무 연결

실제 문항·채점 엔진, 재응시 승인, 진단유형 변경 신청 업무는 별도 구현이 필요하다. 결과 항목의 명칭과 점수표 정의만으로 채점 엔진을 만들지 않는다.
