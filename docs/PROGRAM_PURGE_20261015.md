# 서버 비교과 프로그램 정리 — 2026-10-15

사용자가 서버 비교과 프로그램 8개와 관련 데이터·통계의 전체 삭제를 요청했다.
일반 삭제 API의 이수·로드맵 보호 정책은 유지하고, 명시된 8개 ID만 처리하는
일회성 데이터 정리 스크립트 `backend/scripts/purge_programs_20261015.py`를 사용했다.
자동 배포 마이그레이션이 아니며, 다른 환경이나 새 프로그램에는 자동 적용하지 않는다.

- 프로그램 8, 담당자 연결 9, 신청 8, 신청 이력 17 삭제.
- 설문 4와 답변 58, 알림 4와 읽음 2 삭제.
- 로드맵 연결 칸 7, 칸 이력 6, 프로그램 편입 이력 7 삭제.
- 과거 스냅샷 1과 재생성 이전 상태 1에서 해당 칸만 제거하고 당시 이행률 재계산.
- 멱등 응답 캐시 9 제거. 원본 프로그램 시드 payload 비움; 재시딩 방지용 체크섬·이관 표식 보존.
- 첨부 메타데이터 1 및 실제 파일 1 제거. 서버 내부에 복구용 파일 사본 보관.
- 대상의 찜·벌점·학사 비교과 이력·역량 배점은 0건이었다.
- 학생·인물·진단·상담·마이그레이션 기록 7개 테이블 해시 및 모든 트리거 상태 보존 확인.
- 전체 dc 기본 테이블의 문자열·JSON·배열에서 대상 ID 잔존 참조 0건 확인 후 커밋.
- 서버 API/웹 이미지와 DB 스키마·마이그레이션 127은 변경하지 않았다.

## 검증 및 복구

운영 전체 DB를 로컬로 전송하는 작업은 자동 승인 검토가 개인정보 범위 문제로 거부했다.
서버 내부 백업으로 전환했고 운영 DB의 로컬 다운로드는 수행하지 않았다.

서버 백업: `/opt/dreamcatch/ai/program-purge-20261015/` 아래 `before.dump`,
`backup-list.txt`, `attachments/`, 적용 스크립트, `result.json`.
덤프 목록과 첨부 복사본 해시를 검증했다. 백업은 접근 제한 디렉터리에 보관한다.
복구 시 별도 DB에 백업을 복원한 뒤 해당 행만 선별 복원한다. 이후 업무 데이터를
덮어쓰는 운영 DB 전체 복원은 하지 않는다.

로컬 기존 DB를 별도 `dc_program_purge_20261015_test`로 복원해 롤백 및 확정 리허설을 수행했다.
로컬 대상은 6개였으며 관련 없는 125개 테이블 해시와 트리거가 유지됐다.
로컬 API 목록/통계 200 및 0건 확인. 로컬 원본 DB는 변경하지 않았다.
알림 이력 트리거, PROGRAM_CUTOVER 이관 이력, 지연 FK 검사 순서 문제를 리허설에서
발견해 보완했다. 서버에서는 최종 스크립트 롤백 점검 성공 후 확정했다.

Chrome MCP 서버 `/admin/programs/manage`: 목록 0건(200, 29ms),
통계 프로그램·모집·정원·신청·수료 모두 0(200, 27ms), 실패 요청·콘솔 오류 없음.
학생 `/v2/growth/program`도 프로그램 링크 0개 및 API 정상 응답 확인.

기존 일반 삭제 API의 권한 및 보호 로직은 변경하지 않았다.
다른 세션의 추천 조건 변경(4a011a5)과 로드맵 생성 대상 필터(96e9414)는
이번 운영 데이터 정리의 배포 대상에 포함하지 않았다.
