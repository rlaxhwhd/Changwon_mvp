# 학사 전체 학생 목록

사용자 확정: `/admin/students/all`은 학사 DB 학생 전체를 조회한다. 학부·대학원 및 재학·휴학·제적·수료·졸업을 포함하고 필터로 좁힌다. 로그인 이력·담당 배정으로 전체 목록을 제한하지 않는다.

## 구현

- `academic_students.py`의 읽기 전용 API `/academic-students`, `/academic-students/metadata`를 사용한다. 기존 허용된 학사 읽기 모델에서 조회하며 서비스 계정을 생성하거나 원천을 수정하지 않는다.
- 학생 신분 `1101`, `1102`, `1201`, `1202`를 포함한다. 학적 코드 `0001`~`0005`는 기존 학사 계약에 따라 표시하며 알 수 없는 코드는 `미상`으로 보존한다.
- 이름·학번·학과·진단 유형 검색, 학부/대학원·학과·학년·유형·학적 필터 및 페이지당 20명 조회. 서버 상한은 100명이다.
- 조회 시 `students.1` 메뉴 권한을 검사한다. 학사 기본정보 열람은 상담·로드맵 업무 권한을 부여하지 않는다. 기존 담당 범위 또는 본인 상담 신청 이력이 있는 경우에만 상담·활동 상세 이동을 표시한다.
- 담당 학생 화면은 기존 API를 유지한다. 학사 전체 결과를 담당 학생 캐시에 섞지 않는다.
- 학사 원천을 기준으로 서비스 지표를 LEFT JOIN한다. 동일 검색 내 총원과 페이지는 한 SQL 스냅샷으로 조회한다.

## 검증

- 별도 테스트 DB `dc_regression_20260921064719_5c9e29_test`: `test_academic_students.py` 3건 통과. 미가입 학생 포함, 학적·학부/대학원 필터, 페이지 중복 방지, 메타데이터 총원, 학생 계정 거부, 검색 특수문자, 페이지 한도, 읽기 후 계정 수 불변을 검증했다.
- TypeScript 및 Docker 빌드 검증.
- 실데이터 총 92,514명: 대학원 22,248명, 대학원 졸업 14,913명.
- 첫 페이지 실행계획: JIT 적용 2,289ms → 해당 조회 트랜잭션에서만 JIT 비활성화 779ms. 전역 DB 설정은 변경하지 않았다.
- 필터 선택지 집계: 초기 브라우저 요청 10,998ms. 중복 제거 후 정렬하도록 수정한 실제 DB 함수 호출 818ms. 측정 계층이 다르므로 직접적인 네트워크 개선 배수로 해석하지 않는다.
- 최종 Docker Chrome 검증: 전체 목록 요청 874ms/6,354바이트, 필터 선택지 662ms/13,240바이트(각 1회, HTTP 200). 동일 브라우저 기준 선택지 요청은 10,998ms에서 662ms로 감소했다. 콘솔 오류·가로 넘침 없음.
- 대학원·졸업 복합 필터, 페이지 1→2 중복 없음, 학번 검색 후 1페이지 복귀, 홍길원 기본정보 모달과 담당 상세 이동 버튼을 확인했다.

스키마·원천 데이터 변경은 없다. 복구는 추가 API 라우터와 전체 목록의 `academic` 연결을 되돌리는 코드 배포로 가능하다.
