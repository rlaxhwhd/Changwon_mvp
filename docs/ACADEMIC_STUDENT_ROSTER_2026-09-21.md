# 학사 전체 학생 목록

사용자 확정: `/admin/students/all`은 학사 DB 학생 전체를 조회한다. 학부·대학원 및 재학·휴학·제적·수료·졸업을 포함하고 필터로 좁힌다. 로그인 이력·담당 배정으로 전체 목록을 제한하지 않는다.

## 구현

- `academic_students.py`의 읽기 전용 API `/academic-students`, `/academic-students/metadata`를 사용한다. 기존 허용된 학사 읽기 모델에서 조회하며 서비스 계정을 생성하거나 원천을 수정하지 않는다.
- 학생 신분 `1101`, `1102`, `1201`, `1202`를 포함한다. 학적 코드 `0001`~`0005`는 기존 학사 계약에 따라 표시하며 알 수 없는 코드는 `미상`으로 보존한다.
- 이름·학번·학과·진단 유형 검색, 학부/대학원·학과·학년·유형·학적 필터 및 페이지당 20명 조회. 서버 상한은 100명이다.
- 조회 시 `students.1` 메뉴 권한을 검사한다. 학사 기본정보 열람은 상담·로드맵 업무 권한을 부여하지 않는다. 기존 담당 범위 또는 본인 상담 신청 이력이 있는 경우에만 상담·활동 상세 이동을 표시한다.
- 담당 학생 화면은 기존 API를 유지한다. 학사 전체 결과를 담당 학생 캐시에 섞지 않는다.
- 학사 원천을 기준으로 서비스 지표를 LEFT JOIN한다. 동일 검색 내 총원과 페이지는 한 SQL 스냅샷으로 조회한다.

## 검증

- 별도 테스트 DB `dc_regression_20260921064719_5c9e29_test`: `test_academic_students.py` 3건 통과. 미가입 학생 포함, 학적·학부/대학원 필터, 페이지 중복 방지, 메타데이터 총원, 학생 계정 거부, 검색 특수문자, 페이지 한도, 읽기 후 계정 수 불변을 검증했다.
- TypeScript 및 Docker 빌드 검증.
- 실데이터 총 92,514명: 대학원 22,248명, 대학원 졸업 14,913명.
- 첫 페이지 실행계획: JIT 적용 2,289ms → 해당 조회 트랜잭션에서만 JIT 비활성화 779ms. 전역 DB 설정은 변경하지 않았다.
- 필터 선택지 집계: 초기 브라우저 요청 10,998ms. 중복 제거 후 정렬하도록 수정한 실제 DB 함수 호출 818ms. 측정 계층이 다르므로 직접적인 네트워크 개선 배수로 해석하지 않는다.
- 최종 Docker Chrome 검증: 전체 목록 요청 874ms/6,354바이트, 필터 선택지 662ms/13,240바이트(각 1회, HTTP 200). 동일 브라우저 기준 선택지 요청은 10,998ms에서 662ms로 감소했다. 콘솔 오류·가로 넘침 없음.
- 대학원·졸업 복합 필터, 페이지 1→2 중복 없음, 학번 검색 후 1페이지 복귀, 홍길원 기본정보 모달과 담당 상세 이동 버튼을 확인했다.

스키마·원천 데이터 변경은 없다. 복구는 추가 API 라우터와 전체 목록의 `academic` 연결을 되돌리는 코드 배포로 가능하다.

## 서비스 전용 테스트 계정의 학사 프로필 (2026-10-08)

사용자가 지정한 기존 테스트 계정 두 건에 로컬·서버 PostgreSQL 학사 미러의
더미 기본정보를 추가했다. 원본 Oracle 및 기존 서비스 계정·상담·진단·로드맵은 수정하지 않는다.
더미값은 학부 3학년·재학·평점 3.50이며, 기존 철학과 소속을 학사 조직의
인문대학(1)·철학과(108)에 연결한다. 성별·연락처·졸업일은 생성하지 않는다.

`backend/scripts/add_fixture_academic_profiles.sql`은 학생 번호를 `student1`,
`student2` psql 변수로 받는다. 두 계정이 `dc.person.source='fixture'`인지 확인하고,
기존 학사 신원과 충돌하면 중단한다. `uuid='fixture-profile-20261008'`로 추가 행을 구분한다.
`apply=false`는 시험 후 롤백하고 `apply=true`는 반영한다. 같은 입력으로 다시 실행해도
중복 생성하지 않는다. 복구는 같은 학생 번호와 `remove=true`, `apply=true`로 추가한 행만 삭제한다.

실제 학생 번호·이름·DB 덤프는 저장소에 보관하지 않는다. 반영 전 로컬 백업은
`_workspace/fixture-profile-20261008/before-local.dump`, 서버 백업은
`/opt/dreamcatch/ai/fixture-profile-20261008/before.dump`이다.
학사 전체 스냅샷을 새로 동기화하면 미러의 더미 행도 교체되므로, 필요한 경우 동일 스크립트로
재적용한다. 이 자료를 학교 원본 학적이나 실제 성적으로 해석하지 않는다.

검증: 로컬 시험 적용 후 롤백, 실제 적용, 재적용 시 INSERT 0건, 제거 시험 후 롤백을 확인했다.
로컬 Chrome에서 두 계정의 목록 검색·학사 상세 헤더를 확인했고, 검색 요청은 522ms/326ms,
상세 요청 한 건은 45ms였다. 관련 API는 HTTP 200, 콘솔 오류·경고 없음.
서버에서도 백업 후 시험 적용·롤백·실제 적용·재실행을 확인했다.
양쪽 더미 행 2건의 해시와 DB 컬럼 구조 해시가 일치하며, 적용 이력은 118건을 유지한다.
서버 Chrome은 처음 시연 비밀번호 전달이 자동 승인 검사에 거부되어 로그인 화면에서 중단됐다.
이후 사용자가 로그인 정보를 직접 제공하고 사용을 허용해 일반 로그인 폼으로 접속했다.
서버에서도 두 테스트 계정의 목록 검색과 상세 학사정보 헤더를 확인했다.
검색 요청은 279ms/286ms, 상세 요청은 43ms/37ms였으며 HTTP 200,
콘솔 오류·경고 없음. 화면에 인문대학·철학과·학부·3학년·재학·평점 3.50이 표시된다.
초기 필터 없는 목록 요청은 1,051ms였다. 기존 부팅 API 호출은 유지하며
개별 검색·상세 요청은 사용자 동작마다 한 번씩 발생했다. 로그인 비밀정보는 기록하지 않는다.
