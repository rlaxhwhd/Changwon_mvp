# DB 리버스 엔지니어링 — 메타데이터 추출 절차 (Oracle)

운영 DB의 구조를 **읽기만 해서** 파악하기 위한 절차. 전산원 문의 없이
스키마·관계·데이터 흐름을 복원하는 것이 목표다.

## 대상이 둘이다 (2026-07-29 확인)

| 대상 | 접속 상태 | 쓰는 스크립트 |
|---|---|---|
| **현행 드림캐치 운영DB** (`dream` / 계정 `DREAMCATCH`) | 접속 가능. **자기 소유 스키마**라 전부 조회됨 | **`D_ownership.sql`** ← 지금 여기부터 |
| **학사DB** | 이 계정으로는 접근 경로 없음(`SELECT ANY TABLE` 미보유) | `A`/`B`/`C` — 접근이 열리면 사용 |

`D_ownership.sql`의 목표는 구조 파악에 더해 **각 테이블의 소유권 판별**이다 —
어떤 데이터가 학사DB에서 흘러 들어오고, 어떤 데이터를 이 서비스가 직접 만드는가.

`A`/`B`/`C` 스크립트의 `CHANGE_ME`는 현재 대상 기준으로는 `DREAMCATCH`다.

## 0. 시작 전 안전장치 (필수)

운영 DB다. 실수 한 번이 운영 사고가 된다. **DBeaver에서 두 가지를 먼저 설정한다.**

1. **연결을 읽기전용으로 잠근다**
   `연결 우클릭 → 연결 편집(F4) → 일반(General)` →
   **`읽기 전용 연결(Read-only connection)` 체크** → 확인
   → 이후 이 연결에서는 INSERT/UPDATE/DELETE/DDL이 아예 실행되지 않는다.

2. **연결 유형을 Production으로 바꾼다**
   같은 화면 → `연결 유형(Connection type)` → **Production**
   → 탭이 빨간색으로 표시되고 변경 작업에 확인창이 강제된다.

### 하지 말아야 할 것

| 금지 | 이유 |
|---|---|
| `SELECT COUNT(*) FROM 대형테이블` | 전수 스캔. 수천만 행이면 운영에 부담. 행수는 옵티마이저 통계(`NUM_ROWS`)로 읽는다 — 아래 쿼리들이 그렇게 되어 있다 |
| `SELECT * FROM 학생테이블` | 개인정보 대량 조회. **구조 파악에 실제 행은 필요 없다** |
| `DBA_*` 뷰 조회 | 권한 없으면 에러. 이 스크립트는 전부 `ALL_*`(접근 가능한 객체)만 쓴다 |
| 업무시간 대량 조회 | 가능하면 이른 아침·야간에 |

### 개인정보 취급

**추출하는 것은 메타데이터(구조)뿐이다.** 학번·이름·연락처가 든 테이블도
"컬럼이 무엇인지"만 뽑고 행 데이터는 뽑지 않는다.
예외는 **공통코드 테이블 하나**(상태값·학과코드 체계) — 여기엔 개인정보가 없다.

## 2. CSV 내보내기 방법 (DBeaver)

쿼리 실행(`Ctrl+Enter`) → 결과 그리드 우클릭 → `내보내기(Export resultset)` →
`CSV` → **인코딩 `UTF-8`** (한글 코멘트가 깨지지 않도록) →
저장 위치 `docs/dbmeta/out/` , 파일명은 위 표의 산출물명 그대로.

## 3. 스키마명 치환

각 스크립트 상단에 이렇게 표시된 곳이 있다.

```sql
-- ▼▼▼ 여기만 수정 ▼▼▼
WHERE t.OWNER = 'CHANGE_ME'
```

`A-5` 쿼리 결과에서 **테이블 수가 가장 많은 OWNER**가 보통 학사 스키마다.
그 값으로 모든 스크립트의 `CHANGE_ME`를 바꾼다(DBeaver `Ctrl+H` 일괄 치환).

## 4. 산출물 취급

`out/` 폴더는 **운영 시스템의 스키마 정보**다. 공개 저장소에 올라가면 안 되므로
`out/.gitignore`로 커밋에서 제외해 두었다. 지우지 말 것.
