# 학생 데이터와 라운지 할 일 변경 — 적용·검증 기록

## 5173 개발 서버 404 수정

사용자가 보고한 `http://localhost:5173/api/v1/lounge/weekly-todos` 404를 Chrome MCP에서 재현했다. `.env.local`의 `DC_API_TARGET`이 이전 API인 `http://127.0.0.1:18100`을 가리켰다. 두 서버의 OpenAPI를 비교해 18100에는 주간 경로가 없고, 갱신한 Docker API 18101에는 존재함을 확인했다.

로컬 환경 설정을 `http://127.0.0.1:18101`로 수정했고 Vite가 자동 재시작했다. Chrome MCP에서 실제 localhost:5173 로그인 화면으로 김채원 로그인 후 라운지에 진입해 API 200, 월~일 빈 일정 안내, 콘솔 오류·경고 0건을 확인했다. 개발 StrictMode의 첫 요청 취소 후 두 번째 요청은 정상 완료된다. 앞선 8080 검증만으로 5173 연결까지 정상이라고 판단한 누락을 바로잡았다. 로컬 개발 시 Docker API가 실행 중이어야 한다.

## 확정한 표시 규칙과 구현

- 김채원·김창원에게 개발 예시 점수 `70 / 84 / 63 / 77 / 56`을 입력하고 화면의 예시 안내 문구는 제거한다. 105의 학생별 전용 테이블에 10행을 저장했다. 실제 인정 실적과 공용 배점에는 쓰지 않았다. 개발 환경·fixture·5축 완성 조건을 모두 만족할 때만 사용한다.
- 주간 범위는 한국 시간 월요일~일요일이다. 다음 주가 되면 새 주의 일정으로 교체한다. 날짜가 지난 행은 이번 주 안에서 체크·취소선과 ‘날짜 지남’으로 남긴다. 상담 완료·설문 제출은 ‘완료’로 구분한다. 표시 때문에 상담·설문·수료 상태를 변경하지 않는다.
- 직접 등록 없이 기존 데이터에서 확정 상담일, 선발된 비교과 시작일을 가져온다. 취소·미선발은 제외한다. 이번 요청 범위에서 진단·자격증 예정일은 만들지 않는다.
- 사전 역량향상도 조사는 선발일, 사후·만족도 조사는 수료 후 기존 `PROGRAM_SURVEY` 안내 발생일을 사용한다. 실제 설문 사용 여부·고정된 문항·수료 상태를 확인한다. 별도 설문 예약일 필드는 없다. 날짜가 없는 기록에는 임의 날짜를 부여하지 않는다.
- `GET /api/v1/lounge/weekly-todos`는 로그인 학생 본인의 일정만 반환한다. 교직원 호출은 403이다. GNB 읽음·23시간 필터와 독립적이다. 현재 GNB 자체는 `occurred_at` 기준 23시간이며 이번에 변경하지 않았다.
- 라운지와 내 성장의 추천 일정이 같은 `useWeeklyTodos`를 사용한다. 상담·비교과·설문 변경, 창 포커스 복귀, 한국 날짜 변경 시 다시 조회한다. 긴 목록은 스크롤로 모두 확인한다. 로딩·오류·재시도·빈 상태를 제공한다.

## 적용과 복구

- 로컬 `dreamcatch`에 104~106 적용 및 명시적 예시 시드 실행 완료. 이지우 fixture 0명, 개발 점수 10행, 비활성 이력 보호 트리거 0개다.
- 점수 적용 전 추가 백업: `_workspace/backups/before-competency-20260928.dump`. 백업과 검증 로그·복제 DB는 Git에 넣지 않는다.
- Docker API·웹 이미지를 재빌드하고 healthcheck를 확인했다. 브라우저에 이전 번들이 남으면 강력 새로고침한다.
- 다른 PC에서는 코드 외에 DB 백업도 옮겨야 현재 학생 데이터가 유지된다. 빈 DB bootstrap만으로 이 PC에서 추가한 모든 서비스 데이터가 재현되지는 않는다. 개발 점수 재입력 명령은 `python -m app.seed_core_competency_examples`이며 정확한 두 테스트 계정이 먼저 존재해야 한다.

## 검증 결과

- 신규 테스트 11개 통과: 주 경계·한국 날짜·지난 일정 유지·읽음 독립·취소/권한·설문 상태·누락일·예시 데이터 제한·대상 삭제/원본 보존.
- 전체 격리 회귀: **341 통과, 7 실패, 2 건너뜀**. 변경 전 HEAD의 별도 체크아웃·새 DB에서도 같은 7개가 실패했다(**330 통과, 7 실패, 2 건너뜀**). 실패는 `test_api`의 총 인원 집계, `test_counsel_roadmap_completion` 2개, `test_development_roadmap` 2개, `test_jobs`의 유형 초기 상태, `test_psych_referrals`의 담당 범위 기대값이다. 이번 변경으로 권한 정책을 임의 변경하지 않았다.
- TypeScript/Vite 빌드와 변경된 TS/TSX ESLint 통과. Docker 빌드에서 기존 npm 의존성 감사 경고 11개가 출력되었으며 패키지 버전 변경은 수행하지 않았다.
- Chrome MCP: 실제 8080 서비스에서 김채원·김창원 로그인과 라운지 점수 그래프, 예시 문구 제거, 월~일 빈 상태를 확인했다. 관찰한 김창원 라운지 API 32건은 모두 200, 콘솔 오류·경고 0건이었다. 주간 API는 초기 1회 요청이며 17ms/81bytes(빈 일정)로 관찰됐다. 메타데이터·알림의 기존 주기 갱신은 별도다.
- 복제 DB와 5174 검증 서버(서버 날짜 2026-09-30)에서 8개 일정, 지난 행의 체크/취소선, 오늘/D-day, 사전·사후·만족도 이동을 확인했다. 만족도 16문항 제출 후 완료 표시와 남은 건수 4→3을 확인했다. 실제 서비스 DB에 검증용 일정은 넣지 않았다. 흐린 완료 글자 색을 공통 `--muted-foreground`로 수정하고 재확인했다.
- 개발 서버 React StrictMode에서 주간 요청은 첫 요청 abort 후 정상 1회 완료되며, 기존 설문 상세는 2회 호출된다. Docker 빌드에서는 주간 요청 중복 없이 정상 완료를 확인했다.
- SQL은 학생 범위의 3개 SELECT이며 N+1이 없다. 서비스 DB의 읽기 전용 `EXPLAIN ANALYZE` 실행 시간은 상담 0.596ms, 프로그램 0.272ms, 설문 1.367ms(현재 주 결과 각 0행)다. 이는 당시 로컬 측정이며 대규모 성능 보장이 아니다.
- 기존 초기 공통 bootstrap은 개발 서버 기준 프로그램 약 697KB·채용 약 733KB·메타데이터 약 153KB를 요청한다. 새 주간 API에 이 응답을 재사용하지 않았고, 기존 전체 bootstrap 축소는 이번 작업에서 수행하지 않았다.
