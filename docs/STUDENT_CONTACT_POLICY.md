# 학생 접근 및 미접촉자 정책 — 2026-09-22

사용자 확정. 이전 문서의 담당학생 배정·고위험군·핵심관리대상 규칙을 대체한다.

## 전체 학생 접근

- 담당학생이라는 관리 분류는 없다. 진로취업·심리상담사 모두 전체 학생을 조회·수정할 수 있다.
- 학생별 담당 배정과 다른 상담사 작성 여부로 접근을 제한하지 않는다.
- 예약 담당 상담사는 실제 일정과 중복 예약 방지를 위해 유지한다.
- 교수·조교의 지도학생 권한과 학생 본인 인증, 변경 감사 이력, 동시 수정 버전 검사는 유지한다.

## 홈 미접촉자 현황

학사 DB에서 재학(`hofc_sta_cd=0001`)인 학생만 집계한다. 학년·학부/대학원 제한은 없다. 휴학·졸업·수료·제적은 제외한다. 전체 학생 목록 자체는 모든 학적을 계속 제공한다.

| 탭 | 포함 조건 |
|---|---|
| 진단 | C-CORE 완료 기록 없음 |
| 상담 | C-CORE 완료, 상담 완료 기록 없음 |
| 로드맵 | C-CORE 완료, 상담 완료, 로드맵 초안도 없음 |

상담 신청·예약만으로는 상담 완료가 아니다. 로드맵은 초안 저장부터 생성으로 판정하며 확정·100% 이행을 요구하지 않는다. 각 탭의 목록과 엑셀은 같은 필터를 사용한다. 계정 생성·로그인 여부를 참여로 계산하지 않는다. 개발 테스트의 완료 진단도 현재 테스트 DB 집계에는 포함한다.

## 상담일지 및 검사현황

CARE 7+와 일반 진로취업상담은 같은 일지 양식을 사용한다. 정성진단 5개 항목도 동일하다. T1~T6 변경은 CARE 7+에서만 가능하며 일반 상담은 조회만 제공한다. 기존 완료 상담의 유형 잠금과 재진단 후 새 CARE 7+ 상담에서의 확정 규칙은 유지한다.

검사현황 응시일은 `YYYY/MM/DD`로 표시하고 시간은 출력하지 않는다. 날짜 셀은 중앙 정렬하며 한 줄을 유지한다.

## 배포 및 복구

099 마이그레이션은 두 상담사 역할의 학생·진단·로드맵·검사결과 메뉴 권한을 공유한다. 적용 전 메뉴 권한을 백업하고, 복구는 새 마이그레이션으로 이전 권한을 복원하면서 이전 앱 접근 정책을 함께 배포한다. 이력이나 학생 데이터를 삭제하지 않는다.

## 검증 기록

- 격리 테스트 DB에서 단계별 집계·목록 일치, 휴학생 제외, 초안 생성 판정, 상담사 공동 조회·수정, 일반 상담 유형 변경 차단, 동시 수정·학생 비공개 관련 테스트 49건 통과. 전체 회귀를 실행한 결과는 아니다.
- Docker api/web 빌드 및 반영. Chrome에서 검사현황 날짜 중앙 정렬, 홈 3개 탭, 상담 미참여 목록, 일반 상담의 유형 조회 전용·정성진단 5개, 심리상담사 계정의 CARE 7+ 유형 선택 및 전체 상세 탭을 확인했다. 운영 기록을 수정하는 브라우저 저장은 수행하지 않았으며 쓰기 검증은 격리 DB에서 수행했다.
- 로컬 재학생 8,642명 기준 홈 표시는 진단 미완료 8,636명, 상담 미완료 2명, 로드맵 미생성 0명. 데이터 변경에 따라 달라지는 조회 시점 값이다.
- 집계 SQL EXPLAIN ANALYZE: JIT 기본 설정 약 302ms, 해당 트랜잭션 JIT 비활성 약 43ms. 최종 홈 API 95ms·HTTP 200·1,424바이트, 콘솔 오류와 실패 요청 없음. 전체 학생 목록의 기존 초기 메타데이터 요청은 앞선 화면 확인에서 약 3.6초였으며 전 화면 속도 개선을 의미하지 않는다.
# CARE 7+ 참여학생 집계 기준 (2026-09-22 추가 확정)

- 참여학생은 상담 후 현재 로드맵이 확정(`CONFIRMED`)된 학생이다. 로드맵 활동을 100% 이행할 필요는 없다.
- 진단 유형만 있는 학생과 로드맵 초안·검토 상태의 학생은 참여학생 집계에서 제외한다.
- 홈 참여학생 수·유형 분포와 전체학생 `CARE 7+` 필터는 같은 확정 상태 판정을 사용한다.
- 기존 이관·테스트 로드맵도 확정 상태를 인정한다. 과거 상담 연결 키가 없는 기록을 별도로 탈락시키지 않는다.
- 전체학생 필터는 학사 목록의 학적 필터와 함께 적용한다. 미접촉자 통계의 재학생 한정 규칙과는 별개다.
