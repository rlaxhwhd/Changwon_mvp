# 상담사 홈 DB 전환 (2026-09-14)

학생이 신청한 상담은 접수 목록에 있었지만 홈의 오늘 목록에서는 대기 상태가 제외됐다. 홈은 초기 로딩된 프런트 스토어를 집계했고, 오늘 일정이 없으면 다른 날짜로 대체해 실제 당일 현황과도 달랐다.

## 변경

- `GET /api/v1/counsel-dashboard`: 로그인 상담사의 DB 현황, 오늘 일정, 접수 대기, 학생 유형·집중관리, 로드맵 요청, 담당 프로그램을 조회한다.
- `GET /api/v1/counsel-dashboard/requests/{request_id}`: 선택한 신청의 실제 문진 답변과 상담 이력 등을 조회한다. 같은 학생의 다른 신청을 혼합하지 않는다.
- 오늘은 한국 시간의 **상담 예약일** 기준이며 대기·확정·완료를 포함한다. 취소는 제외한다. 다른 날짜의 대기는 접수함에서 확인한다. 접수함은 최신 5건을 표시하고 배지는 전체 대기 건수다.
- 홈 상담은 로그인 사용자가 배정된 담당자인 건만 표시한다. 학생 유형·집중관리와 로드맵은 기존 API의 권한·학생 범위를 재사용한다. 심리상담 브리핑에는 CARE 로드맵·진단 정보를 제공하지 않는다.
- 담당 프로그램은 표시 이름 대신 `created_by` UID로 조회한다. 담당 프로그램이 없으면 빈 목록을 표시한다.
- 고정 성과 목표와 가짜 AI 질문 생성 동작을 제거했다. 비율은 DB 집계에서 계산하며 문진은 저장된 질문·답변만 표시한다.
- 진입, 창 포커스 복귀, 상담 변경 이벤트, 보이는 탭에서 30초 간격으로 갱신한다. 수동 새로고침도 제공한다. 최초 조회 실패 시 오류를 표시하며 0건으로 대체하지 않는다. 갱신 실패 시 이전 데이터와 오류를 함께 표시한다.

## 데이터 및 배포

기존 PostgreSQL의 `dc.counsel_request`, `dc.counsel_record`, 학생·진단·로드맵·프로그램 테이블을 조회한다. 새 테이블이나 데이터 복사, Oracle 변경은 없다. 프런트와 API를 함께 배포해야 한다. 실행 중인 로컬 API에는 새 라우터를 반영하도록 재시작했다.

홈 실행 경로에서 JSON/샘플 데이터를 읽지 않는다. `backend/seeds`의 과거 초기화 자료는 기존 DB 반입 감사 기록으로 보존하며 홈의 조회 원본으로 사용하지 않는다.

## 검증

- 프런트 빌드 및 변경 TypeScript 파일 ESLint 통과.
- 격리된 `dreamcatch_dashboard_20260914_test` DB에서 `tests/test_counsel_dashboard.py` 11개 통과. 테스트 쓰기는 트랜잭션 롤백한다.
- 대기·확정·완료, 취소·다른 날짜 제외, 담당자·상담 유형 분리, 날짜 대체 방지, 새 신청과 상태 변경 반영, 신청별 문진, 최신 5건과 전체 건수 분리, JSON 프로필 없는 신규 학생, 접근 권한, 프로그램 소유자 범위를 검증했다.
- 실제 로컬 DB와 브라우저에서 진로·심리 홈, 오늘 대기 상담 표시, 포커스 갱신, 최초/갱신 오류 및 재시도 복구를 확인했다. 브라우저 오류는 없었다. 실제 DB에는 검증용 상담 신청을 생성하지 않았다.
