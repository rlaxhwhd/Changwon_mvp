# 상담일지 공용 템플릿 (2026-09-17)

## 확정된 업무 규칙

- 상담 진행(`/admin/counsel/session/:studentId`)과 상담일지 작성(`/admin/counsel/journals`)은 `CounselRecordFields`를 함께 사용한다.
- 상담 방식은 대면·전화·화상·이메일, 상담 일시는 한국 시간이다. 일지에 실제 진행 정보를 기록하며 기존 예약 슬롯을 변경하지 않는다.
- 2026-09-22 변경: CARE 7+와 일반 진로취업상담은 동일 양식과 정성진단 5개 필수 항목을 사용한다. 일반 진로취업상담은 T1~T6 유형을 조회만 하며 변경값은 서버에서도 거부한다. CARE 7+ 상담에서만 최종 유형을 선택한다. 심리상담 양식은 유지한다.
- 모든 진로취업·심리상담사는 학생 배정이나 일지 작성자와 무관하게 전체 학생의 기록을 조회·수정한다. 변경자 감사 이력, 버전 충돌 검사, 학생 본인에게 내부 내용을 숨기는 규칙은 유지한다.
- 상담내용은 프로그램 현황 체크·입사지원 현황 체크 중 하나 이상을 선택해 각각 입력한다. 선택한 항목은 모두 내용이 필요하다. 임시저장은 미완성 상태를 허용한다.
- AI 상담일지 카드는 디자인만 제공한다. 생성 버튼은 비활성화하고 호출·시연 생성은 하지 않는다. AI 내용은 학생 비공개이며, 현재 API는 임의 생성문을 받지 않는다.
- 학생에게 상담 본문·정성진단·AI 일지·후속 조치를 공개하지 않는다. 별도 공개 코멘트만 학생 상담기록에 반환한다. 처리 이력 API에서도 내부 본문을 반환하지 않는다.
- 긴급관리/위험도 입력은 추가하지 않는다. 첨부파일은 기존의 연결 준비 상태를 유지한다.

## 유형 결정

진단 결과와 상담 확정은 `dc.student_type_event`에 원본 이력으로 남는다. `dc.current_student_type`은 상담 이력이 있으면 최근 상담 유형을, 없으면 최근 진단 등 기존 이력의 유형을 반환한다. 재진단부터 재상담 사이에는 기존 상담 유형을 유지한다.

새 CARE 7+ 상담 완료만 상담 유형 이벤트를 발행한다. 임시저장이나 완료된 상담일지 수정은 학생 유형을 변경하지 않는다. 완료된 일지의 유형 선택은 잠기며 서버에서도 변경을 거부한다. 기존 상담 유형이 있으면 그 결정 이후의 재진단 유형 이벤트가 있어야 새 유형을 확정할 수 있다. 재진단 주기나 외부 진단 연계 계약은 이번에 새로 정의하지 않는다.

유형이 달라지면 **새 유형의 후속진단도 필수**다. 유형 변경 후 미완료 후속진단 때문에 취업지원이 제한되는 기존 게이트를 유지한다. 학생 목록·상세, 상담 신청, 비교과 대상, 취업지원 게이트, 로드맵 유형 조회가 같은 공통 뷰를 사용한다. 기존 로드맵의 불변 생성 근거를 소급 수정하지 않는다.

## DB·API

- `093_counsel_record_template.sql`: 기존 `dc.counsel_record`에 nullable `template jsonb` 추가. 문서 단위로 함께 읽고 쓰는 고정 크기 입력이므로 별도 항목 테이블·JSON 검색 인덱스를 만들지 않는다. JSON object·버전 CHECK와 Pydantic 세부 검증을 적용한다.
- `094_counsel_type_priority.sql`: `(student_uid, (source='counsel') DESC, decided_at DESC, id DESC)` 인덱스와 `current_student_type` 뷰, `student_list` 공통 조회 연결.
- `GET /counsel-requests/{id}/record-context`: 권한 범위 내 교직원에게 현재 일지, 최근 진단 유형, 완료 후 유형 잠금 여부를 반환한다. 학생 호출은 거부한다.
- 기존 `PUT /counsel-requests/{id}/record`와 `POST /counsel-requests/{id}/complete`에 `template`을 연결한다. 서버가 선택한 내용으로 기존 `summary`를 생성하므로 인쇄·내보내기와 호환된다.
- 완료 API는 새 템플릿 사용 시 `expectedRecordVersion`을 요구한다. 신청 버전뿐 아니라 다른 창에서 바뀐 일지도 덮어쓰지 않는다. 일지 저장은 편집 시작 버전을 전송한다.
- 기존 양식의 본문은 `legacySummary`로 서버가 보존한다. 클라이언트가 보내는 보존값을 신뢰하지 않는다. 재분류·자동 요약으로 원문을 변형하지 않는다.
- 학생용 상담기록은 `template: null`, `summary: ''`, `followUp: ''`로 반환한다. 완료 기록에만 접근할 수 있다.

## 마이그레이션·복구

마이그레이션은 기존 값의 일괄 변경이나 삭제 없이 추가된다. `lock_timeout=3s`, `statement_timeout=30s`로 잠금 대기를 제한한다. 인덱스는 로컬의 작은 이력 테이블에 트랜잭션으로 생성한다. 대형 운영 테이블 적용 시에는 쓰기량과 규모를 측정하고 별도 CONCURRENTLY 배포 절차를 마련해야 한다.

앱 롤백 시 nullable 열을 유지할 수 있다. 상담 우선 규칙을 롤백해야 한다면 원래 `student_list` 정의와 앱 조회를 **새 마이그레이션**으로 함께 복구한다. `template`을 삭제해야 할 때는 먼저 원문을 내보내고 다른 신규 마이그레이션으로 처리한다. 이미 적용된 093/094를 수정하거나 이력을 삭제하지 않는다.
