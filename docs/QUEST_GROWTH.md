# 퀘스트 성장 · 출석 · XP (2026-09-16 · 레벨 체계 2026-10-20 최종 확정)

> 2026-09-29 변경: 일일은 출석·TOEIC 2개로 확정되었고 월간·학기는 관리자 대상별 편성으로 전환되었다. 관리자 화면·활동 판정은 [퀘스트 관리 구현 기록](QUEST_MANAGEMENT_2026-09-29.md)을 따른다.
> **2026-10-20 최종 확정:** 아래 「성장 레벨 체계」가 정본이다. 이전의 「학년별 누적 상한 = 학년 × 25 Level」과 일일 3개 기준 학기 총량 계산(259개 / 19,800 XP)은 폐기했다.

## 성장 레벨 체계 (2026-10-20 사용자 최종 확정)

**학기 레벨은 0~12.5, 학년 레벨은 0~25이며 매 학년 초기화한다. 누적 성장 레벨은 각 학년에서 획득한 성장 레벨을 합산하여 최대 100LV까지 기록한다. 장학금과 주요 보상은 현재 학기의 성장도를 기준으로 지급하고, 누적 성장 레벨은 학생의 전체 대학생활 성장 이력을 나타내는 지표로 활용한다.**

| 구분 | 범위 | XP | 초기화 | 용도 |
|---|---|---|---|---|
| 학기 성장 레벨 | 0 ~ 12.5 LV | 학기당 최대 12,500 XP | 학기마다 | **장학금·주요 보상 판정** |
| 학년 성장 레벨 | 0 ~ 25 LV | 학년당 최대 25,000 XP | 학년마다 0부터 | 현재 성장 표시 |
| 누적 성장 레벨 | 0 ~ 100 LV | 최대 100,000 XP | 초기화 없음 | 프로필 성장 기록·전체 랭킹·누적 배지·졸업 인증·장기 성취 보상 |

- 1 LV = 1,000 XP. 세 상한을 모두 지킨다 — 지급 XP = min(요청 XP, 학기 남은 XP, 학년 남은 XP, 누적 남은 XP). 초과분은 적립·이월하지 않는다.
- **모든 XP는 관리자가 설정한 학기에 속한다.** 학기 밖(방학)이나 학기 미설정이면 출석·TOEIC·월간·학기 퀘스트 모두 0 XP다. 시스템이 학기 날짜를 임의로 만들지 않는다.
- **학기 기간은 연도 없이 1학기·2학기의 월/일로 정하고 매년 반복한다**(2026-10-20 사용자 확정). 시스템관리자가 `/admin/quests/manage` → 학기 편성 탭의 달력(react-day-picker, 연도·요일 미표시)에서 설정한다. 정본은 코드 `QUEST_TERM`(FIRST·SECOND, payload `{start:"MM-DD",end:"MM-DD"}`, 131). 연도별 학기는 서버가 계산한다 — 키 `2026-2`, 이름 「2026학년도 2학기」. 종료 월/일이 시작보다 앞이면 다음 해에 끝나는 학기(예: 09-01~02-28 → 2026-09-01~2027-02-28, 2027-01은 2026학년도 2학기). 02-29는 평년에 02-28로 계산한다. 두 학기 기간은 겹칠 수 없다. 월간·학기 퀘스트 편성도 이 학기 목록에서 고르며, 편성은 저장 시점의 시작·종료일을 그대로 가진다.
- 연도별 학기 일정 코드 `QUEST_SEMESTER`(091)는 131부터 XP·편성 기준이 아니다(코드관리에서 숨김, 데이터는 보존).
- **신규 가입자:** 고학년이 처음 가입해도 그 학년 LV 0부터 시작한다(3학년이라고 LV 50·51을 자동 지급하지 않는다). 늦게 시작한 학생도 같은 학년 학생과 같은 출발선에서 경쟁한다.
- **학기 성장 보상 단계**(코드 `QUEST_SEMESTER_TIER`, 기준 XP 고정·명칭만 수정 가능):

  | 학기 성장 | 코드 | 보상 |
  |---|---|---|
  | 3 LV (3,000 XP) | `BASIC` | 기본 보상 |
  | 6 LV (6,000 XP) | `GROWTH` | 성장 보상 |
  | 9 LV (9,000 XP) | `EXCELLENT` | 우수 보상 |
  | 11 LV (11,000 XP) | `TOP` | 최우수 보상 |
  | 12.5 LV (12,500 XP) | `BEST` | 학기 최고 성취 |

  1학년과 4학년 모두 같은 0~12.5 LV 범위에서 경쟁하므로 공정하다. 장학금 집행은 시스템 밖 절차이며, 화면은 현재 단계와 다음 단계까지 남은 XP를 보여 준다.
- **화면 표시 예**(4학년, 대학생활 동안 54 LV 성장): `현재 성장 4학년 LV 0 / 25` · `이번 학기 1학기 LV 0 / 12.5` · `누적 성장 54 / 100LV`. 학기 레벨은 정수 LV로 표시하고 상한 도달 시에만 12.5로 표시한다.
- XP 기준값: 일일 2개(출석·TOEIC) × 50 XP, 월간·학기는 관리자가 편성한 퀘스트별 XP. 학기 목표 12.5 LV = 12,500 XP, 학년 목표 25 LV = 25,000 XP.

## 출석 · 일정 규칙

- 출석은 일일 퀘스트 1개로 포함한다. KST 하루 한 번 버튼으로 체크하고 자정에 당일 상태를 초기화한다. 오늘 미출석이면 어제까지의 연속 기록을 유지하며, 하루를 빠뜨리면 끊긴다.
- 출석·TOEIC XP는 **등록된 학기의 월~금에만** 지급한다. 주말·방학은 출석만 저장한다. 공휴일 제외 규칙은 설정하지 않았다.
- 학기 일정 미등록 시 XP를 지급하지 않으며, 화면은 「학기 일정이 아직 등록되지 않아 XP가 지급되지 않습니다」로 이유를 밝힌다. 일정/XP 변경 후 과거 출석을 소급 보상하지 않는다.
- 2026-10-20 「일일퀘스트를 해도 XP가 오르지 않는다」 원인: 활성 학기 일정(당시 `QUEST_SEMESTER`)이 없어(검증용 2093 학기만 비활성) 지급이 0이었다. 코드 결함이 아니라 학기 미등록이다. TOEIC은 그 주의 TOEIC 미션이 게시돼야 완료할 수 있다.

## 운영 화면

- `/v2/growth/quest`: 연속 출석, LV와 그 아래 1,000 XP 게이지, 실제 출석 달력, 최근 7/30일 일별 획득 XP 그래프. 그래프의 일별 표도 제공한다.
- 기존 StudentStatCards를 재사용하고 퀘스트 페이지 안에서만 레벨 배치를 조정했다. 다른 요약 카드 화면은 변경하지 않았다.
- 미정 예시 퀘스트를 학생 실적으로 바꾸지 않았다. 현재 실제 완료 가능한 퀘스트는 출석이며 나머지 일일·월간·학기 퀘스트는 등록 준비 상태다.
- `/admin/system/codes` → **퀘스트 · XP 보상**: DAILY/MONTHLY/SEMESTER의 숫자 입력으로 지급 XP 수정. 0~100,000 정수, 감사 이력/낙관적 버전 검사 적용. 변경 후 새 완료에만 적용한다.
- ~~같은 화면 → 퀘스트 · 학기 운영 일정(연도별 YYYY-MM-DD)~~ — 131에서 `/admin/quests/manage` 학기 편성 탭의 월/일 1·2학기 설정으로 대체.
- 보상 미리보기, 관리자 퀘스트 정의/출제 화면, 비교과 개설 시 XP 설정·이수 연계는 후속 작업이다. 사용자 확인에 따라 이번 범위에서 자동 지급하지 않는다.

## DB/API와 확장 계약

Migration 090(DDL), 091(운영 코드 데이터), 130(원장에 지급 시점 `grade`·`semester_code`, 인덱스 `(student_uid,semester_code)`·`(student_uid,grade)` INCLUDE granted_xp, `QUEST_SEMESTER_TIER` 5단계), 131(`QUEST_TERM` FIRST·SECOND, 미설정·비활성으로 시작). 기존 migration 수정 없음.

학기 XP는 학기 시작~종료일의 `earned_on` 합계로 계산한다(`growth_xp_event_daily` 인덱스) — 월/일을 나중에 바꾸거나 131 이전 행의 `semester_code`가 옛 코드여도 일관된다. `semester_code`는 지급 당시 기록으로 남는다. API: `GET /system/quests/terms`, `PUT /system/quests/terms/{FIRST|SECOND}` `{expectedVersion,start,end}`(시스템관리자, 버전 검사, `admin_event(entity=quest_term)` 감사).

대시보드 응답 `growth`: `semester{code,label,xp,level,maxLevel=12.5,maxXp,tier,nextTier}`(학기 미등록이면 null) · `grade{grade,xp,level,maxLevel=25,maxXp}` · `cumulative{xp,level,maxLevel=100,maxXp}` · `tiers[]`. 학기·학년 레벨은 원장 합계로 파생하며 별도 집계 테이블이 없다. 기존 `level`·`levelCap`(=25)·`xpInLevel`·`atCap`은 **학년 레벨** 기준이고 `totalXp`는 누적 XP다.

| 테이블 | 목적 / 무결성 |
|---|---|
| `dc.quest_growth_account` | 학생 PK/FK, 지급 XP 누계. 원장 입력과 같은 트랜잭션으로 갱신 |
| `dc.quest_attendance` | 학생+KST 날짜 복합 PK, 중복 출석 방지 |
| `dc.growth_xp_event` | 출처/완료 식별자, 당시 보상 코드 버전·요청 XP·실지급 XP·상한·지급일 기록. 학생+출처+완료 식별자 UNIQUE |

GET `/api/v1/quests/dashboard?month=YYYY-MM`: 인증 학생 본인만 조회. 누계·레벨·연속 출석·조회 월 출석일·최근 30일 그래프·보상 코드·학기·완료 집계.
POST `/api/v1/quests/attendance`: 학생·날짜·XP를 클라이언트가 정하지 않는다. 서버 KST와 학기 설정으로 처리한다. 중복 요청은 성공 응답하되 추가 지급은 0.

원장 기반 `grant_xp()`는 **내부 서비스 함수**다. 임의 XP 지급 HTTP API는 없다. 향후 퀘스트/비교과 완료 처리에서 다음을 지킨다:

1. 기존 API가 실제 완료·권한을 검증한다. 브라우저가 보낸 완료 주장만으로 지급하지 않는다.
2. 같은 DB 트랜잭션에서 `grant_xp()` 호출. 출처 `QUEST` 또는 `PROGRAM`, source_key는 영속 완료 ID. 매 요청마다 UUID를 새로 만들어 재지급하지 않는다.
3. 퀘스트는 적용한 코드/버전과 XP를 전달한다. 비교과는 개설 때 확정·저장한 XP를 전달한다. 예를 들어 200 XP도 학기·학년·누적 상한 적용을 받으며, 학기 밖 완료는 0 XP다.
4. 수정·취소·환수 정책은 아직 미정이다. 원장을 직접 수정하거나 음수 지급으로 임의 환수하지 않는다.

학생별 advisory lock과 계정 행 잠금, UNIQUE로 동시 지급·중복 요청을 제어한다. 같은 학생의 대시보드 읽기도 같은 advisory lock으로 지급 중간 상태를 피한다. 앱 계정은 원장/출석 SELECT·INSERT만 갖고 UPDATE/DELETE 권한은 없다. 학년 미등록이면 적립 시 409로 처리한다.

주요 인덱스: 출석 `(student_uid,attended_on)`, 원장 `(student_uid,earned_on) INCLUDE(granted_xp)`, 중복키 `(student_uid,source_type,source_key)`, 보상 코드 FK 인덱스. 학생당 30일 데이터만 그래프로 전송한다. 운영 데이터 소급 이관은 하지 않는다.

## 검증 / 복구

- 2026-10-20 월/일 학기: 격리 DB 퀘스트·미션·코드 회귀 71 통과(실패 2 = 기존 test_roadmap). 학기 API 권한·형식(02-30·13-01·연도 포함)·겹침·버전 충돌, 해를 넘기는 2학기(2031-01-10 → 2030학년도 2학기), 편성 학기 목록 검증. 로컬 Docker 131 적용 후 Chrome 학기 편성 탭 달력(캡션 「3월」·요일/연도 없음, 접근성 라벨 「3월 2일」)으로 1학기 03-02~06-20·2학기 09-01~12-20 저장(로컬 전용 값) → 감사 2건, 학기 목록 2025~2027 생성·2026학년도 2학기 기본 선택, 학생 대시보드 학기 2026-2·학기 XP 50 확인, 콘솔 오류 0.

- 2026-10-20 레벨 체계: 격리 DB 퀘스트·미션 회귀 63 통과(학기 12,500·학년 25,000·누적 100,000 상한, 방학 0 XP, 진급 후 학년 0부터, 고학년 신규 LV 0, 원장 grade·semester_code 기록). 실패 2건은 기존 `test_roadmap` 변경요청 실패로 무관. 로컬 Docker 130 적용 후 시스템관리자 API로 로컬 학기 `YEAR2026_2`(2026-09-01~12-31)를 등록하고 학생 출석 → 50 XP 지급·학기/학년/누적 표시 확인, 콘솔 오류 0. **서버는 관리자가 실제 학기 일정을 등록해야 XP가 지급된다.**

- 프런트 빌드·타입 검사·변경 파일 ESLint 통과.
- 기존 코드관리 테스트 8개를 포함한 최종 회귀 검사 16개 통과. Chrome에서 관리자 XP 숫자 입력 및 학기 일정 입력 폼도 확인했다.
