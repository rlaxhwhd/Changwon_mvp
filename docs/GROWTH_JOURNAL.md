# 경험일지 DB/API 연결 보완 (2026-09-16)

## 정본과 권한

경험일지는 이미 025/026 마이그레이션에서 만들어진 `dc.growth_entry(kind_code=JOURNAL)`을 사용한다. 별도의 일지 테이블이나 상담사용 복제 테이블을 만들지 않는다. `growth_profile`의 학생 FK, 분류 코드 FK, `growth_event`의 변경 이력과 논리삭제를 유지한다. 상황·역할·행동·결과·배운 점·자소서 메모는 종류별 검증된 JSON 본문이며 소유자·날짜·분류·버전은 일반 컬럼이다.

- 학생 본인: 작성·조회·수정·북마크·삭제.
- 진로취업상담사 학생 상세(`/admin/students/changwon` 포함): 동일한 행을 읽기 전용 조회. 기존 `students.0` 메뉴 권한과 `staff_student_scope`를 모두 통과해야 한다. 다른 교직원의 기존 범위를 확대하지 않는다.
- 다른 학생: 404. 교직원의 작성·수정·삭제: 403.
- 기존 Idempotency-Key, 프로필/행 버전, 학생 단위 트랜잭션 잠금을 재사용한다.
- 일지 내용은 권한 있는 상담사에게 보인다. 별도의 비공개 일기 기능을 새로 정의하지 않았다.

## 변경

- 새 `092_growth_entry_timeline.sql`: 활성 자료의 학생별 정렬과 학생+종류별 정렬 인덱스. 기존 데이터 변경/복제/삭제 없음. 날짜 DESC NULLS LAST, 수정일 DESC, ID 순서를 API와 일치시켰다.
- 잘못된 날짜는 SQL 실행 전에 422로 거부.
- 수정 URL 직접 방문: 서버 적재 후 편집기를 구성. 없는 ID를 신규 등록으로 처리하지 않는다. 편집 시작 시 버전을 유지하여 나중 버전을 덮어쓰지 않는다.
- 작성/수정 폼 저장 중 입력 잠금, 제목/본문 길이 제한, 삭제 버튼, 한국 날짜 기본값.
- 공통 스토어의 처음 100건만 읽던 누락 수정: 학생별 100건 페이지를 끝까지 순차 적재한다. 현재 화면의 로컬 검색·통계 계약을 유지하는 선택이다. 전체 학생을 읽지 않지만 한 학생의 누적 자료가 매우 많으면 총 응답량은 증가한다. 향후 대규모 누적 시 화면별 서버 페이지네이션과 별도 집계를 분리해야 한다.
- 조회 실패/적재 중/빈 목록 구분, 재시도. 화면 재진입 시 재조회. 로그아웃 중 이전 요청이 완료되어도 캐시에 복원하지 않는다.
- 주요 키워드는 실제 일지 태그로 집계한다.
- 상담사 성장 탭: 실제 일지 건수, 한글 분류, 역할·행동·결과·메모 상세 열람.
- AI 자소서: 성장 스토어 적재/구독을 연결하고 첫 5건 제한을 제거하여 기록을 첨부할 수 있다. **AI 생성 자체는 기존 AI_DRAFT_SAMPLE 시연 코드이며 이번에 실제 모델 연동을 구현한 것은 아니다.**

## 기존 API

`/api/v1/students/{identity}/growth/entries` GET/POST,
`/entries/{entry_id}` GET/PATCH,
`/entries/{entry_id}/delete` POST.
별도 중복 API는 만들지 않았다. 날짜 검증만 보강하고 기존 계약을 유지했다.

## 검증

- 독립 DB `dc_regression_20260916084738_047991_test` 전체 마이그레이션/시드 성공.
- 성장 관련 API 테스트 23개 통과. 학생 작성 후 상담사 동일 내용/버전 조회, 교직원 변경 차단, 타 학생 차단, 중복 생성 방지, 수정 충돌, 삭제 비노출, 잘못된 날짜 422.
- Node 기반 공통 스토어 검증: 101건 모두 적재, 실패 상태, 로그아웃 중 요청 결과 폐기 통과.
- TypeScript/프로덕션 빌드/변경 파일 ESLint 통과. 빌드의 Vite CSS 플러그인 처리시간 안내 및 Python 기존 deprecation 경고는 남아 있다.
- 독립 DB에서 1만 건을 트랜잭션 안에 생성한 후 EXPLAIN ANALYZE, 끝에 ROLLBACK. 첫 100건 전체/일지 조회 모두 timeline 인덱스 사용, 실행 0.076/0.073ms. 짧은 합성 본문에 대한 개별 SQL 측정이며 전체 API/전체 목록 속도 보장이 아니다.
- 로컬 18100 API 재시작 후 HTTP 직접 확인: 학생 GET 200 약36.5ms/8293B, 담당 상담사 GET 200 약49.1ms/8293B, 다른 학생 GET 404. 개인정보 본문/인증 토큰은 기록하지 않았다.
- **사용자 요청으로 Chrome MCP 미사용. 실제 브라우저 레이아웃·콘솔·네트워크는 이번 작업에서 미검증.**

## 적용과 복구

092는 테스트 DB 검증 후 로컬 DB에 적용했다. 적용된 025/026/092 파일을 수정하지 않는다. 인덱스는 이전 API와 호환되므로 앱만 되돌려도 된다. 인덱스를 제거해야 하면 두 인덱스만 삭제하는 새 전진 마이그레이션을 작성한다. 일지/프로필/이력은 삭제하지 않는다. 잠금 대기 3초/명령 30초 제한으로 사용 중인 테이블을 오래 막지 않으며 대규모 운영 DB에는 별도의 concurrent 배포 계획이 필요하다.
