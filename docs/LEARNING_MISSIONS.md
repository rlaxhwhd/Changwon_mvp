# 주간 학습 미션

## 화면과 출제 흐름

- 최고관리자 상단 메뉴: 퀘스트 관리 → 미션 관리 (`/admin/quests/missions`). 메뉴 이름·활성 여부·노출 순서는 기존 메뉴관리에서 유지한다.
- 문제 풀: TOEIC 영단어, NCS, GSAT를 등록·검색·수정·사용 중지한다.
- TOEIC: 영단어, 뜻, 분류, 예문, 추가 허용 정답, 해설을 관리한다. 퀴즈는 뜻을 보고 영단어를 입력하는 방식이다.
- NCS/GSAT: 문제·분류·서로 다른 보기 2~5개·정답·해설을 직접 입력한다.
- 주 시작일을 선택하고 최대 선택 개수를 10개 또는 20개로 설정하고 문제 풀에서 선택한다. 선택 순서가 학생 문제 순서다.
- 비공개 저장은 학생 노출을 중단한다. 게시하면 한국 시간 월요일~일요일에 해당하는 주에 학생에게 노출한다. 미래 주간도 미리 게시할 수 있다.
- 게시 시 문제 풀의 현재 내용을 주간 목록에 복사한다. 문제 풀만 수정해도 게시 내용이 자동 변경되지는 않는다.
- 영단어 40개는 시작용 문제 풀이다. 자동 게시하지 않으며 외부 기출문제집을 복제하지 않았다. 필요에 따라 관리자가 내용을 수정한다.

학생 화면 `/v2/growth/mission`은 실제 게시된 미션만 표시한다. 전공 퀴즈, 임의 합격 기준, 고정 출석 현황을 제거했다.
학습 → 문제풀이 시작 → 모든 답안 제출 → 서버 채점 → 정답·오답·해설 확인 흐름이다.
`/v2/growth/mission-log`는 서버에 제출한 본인 풀이를 페이지 단위로 조회한다.

## 데이터와 권한

- `dc.mission_question`: 문제 풀, 활성 여부, 버전, 최종 수정자.
- `dc.mission_week`: 유형별 주간 출제, 게시 여부, 문제 내용 사본, 버전. 주 시작일+유형 유일.
- `dc.mission_attempt`: 학생별 풀이 시작 시 문제 사본, 제출 답안, 채점 결과, 시작·제출 시각.
- 관리자 API는 AUTH0006 권한을 검사한다. 학생 API는 학생 본인만 허용하며 학생 ID를 요청 입력으로 받지 않는다.
- NCS/GSAT의 정답·해설은 제출 전 학생 응답에서 제외한다. TOEIC 학습 화면에는 단어를 보여주지만 채점은 서버에서 수행한다.
- 영단어는 Unicode NFKC, 대소문자, 앞뒤·연속 공백을 정규화한 뒤 정답 또는 허용 답안 전체와 비교한다. 일부 문자열만 일치하면 오답이다.
- 시작한 풀이에는 당시 문제와 정답을 저장한다. 이후 문제 수정·비공개·주간 변경으로 이미 시작한 풀이의 채점 기준을 바꾸지 않는다. 시작한 풀이는 주가 지나도 제출할 수 있다.
- 같은 주간 버전의 미제출 풀이는 재사용한다. 같은 답안 재전송은 같은 결과를 반환하고, 제출 후 답안 변경은 409로 거부한다.
- 제출 전 입력은 브라우저 메모리에서만 유지한다. 새로고침하면 입력은 초기화되지만 제출된 이력은 보존한다.
- 관리자 수정·게시에는 버전 충돌 검사와 `dc.admin_event` 감사 이력을 적용한다.
- 경험치·레벨·보상 및 퀘스트 대시보드의 완료 판정과는 연결하지 않는다. 이 기준은 사용자 확정 후 별도 구현한다.

## API

- GET /system/missions/questions?kind=TOEIC|NCS|GSAT&q=&page=
- PUT /system/missions/questions/{id} (id=0 신규; expectedVersion 필수)
- GET, PUT /system/missions/weeks/{월요일 날짜}/{TOEIC|NCS_GSAT}
- GET /missions/current
- POST /missions/attempts (weekId, version)
- POST /missions/attempts/{uuid}/submit (answers: 문제 ID → 문자열 또는 보기 인덱스)
- GET /missions/history?page=

## 마이그레이션과 복구

적용 스킬: `.claude/skills/postgres-patterns`, `database-migrations`, `frontend-design`.

076은 신규 스키마만 추가한다. 기존 업무 테이블의 대량 갱신·삭제·컬럼 변경은 없다.
077은 관리자 메뉴 데이터, 078은 단어 문제 풀 데이터이며 DDL과 분리했다.
테스트 DB에 먼저 적용하고 기능 검증 후 로컬 DB에 기존 `app.migrate`로 적용한다.
테스트 DB에는 기존 062 마이그레이션 체크섬 불일치가 남아 있어 해당 이력을 수정하지 않고 076~078 파일만 트랜잭션과 마이그레이션 잠금으로 적용했다. 로컬 DB 기존 체크섬은 일치했다.

운영 복구는 새 전진 마이그레이션으로 퀘스트 메뉴를 비활성화하고 앱을 이전 버전으로 되돌린다. 학생 풀이를 보존하기 위해 테이블·문제·기록 삭제를 자동 롤백으로 제공하지 않는다. 신규 빈 테이블의 일반 인덱스를 생성하므로 기존 대규모 테이블의 인덱스 잠금은 발생하지 않는다.

## 검증

권한 차단, 비공개·주간 노출, 버전 충돌, 정답 미노출, 유형별 서버 채점, 학생별 이력 격리, 중복 제출, 기존 풀이 사본 보존, 정확한 단어·허용 답안 비교를 API 통합 테스트로 검증한다.

## 선택 개수 및 랜덤 추가 (2026-09-16)

- 주간 `selection_limit`은 10 또는 20이며 API 저장 시 개수 초과를 거부한다. 신규 화면 기본값은 10, 기존 주간 목록의 마이그레이션 기본값은 20이다.
- 기존 20개 초과 목록은 자동 삭제하지 않는다. 한도에 맞게 수정한 뒤 다시 저장할 수 있다.
- 랜덤 생성은 현재 조회 중인 유형(TOEIC/NCS/GSAT), 난이도, 적용된 검색어에 맞는 전체 문제 풀을 대상으로 한다. 페이지 단위로 제한하지 않는다.
- 기존 선택을 유지하고 목표 개수까지 부족한 문제만 무작위로 추가한다. 기존 3개 + 목표 10개라면 7개 추가한다. 기존 선택은 중복 후보에서 제외한다.
- 이미 목표 개수에 도달하면 랜덤 추가하지 않는다. 후보가 부족하면 422 안내를 표시하고 기존 목록을 유지한다.
- 선택 전체 삭제는 편집 중인 선택 목록만 비운다. 문제 풀의 원본·게시 이력·학생 풀이를 삭제하지 않으며 주간 저장 전에는 서버 목록도 바뀌지 않는다.
- 읽기 전용 GET `/system/missions/questions/random?kind=TOEIC&count=10&excludeIds=1` 사용. count는 목표 총수, excludeIds는 기존 선택 ID다.
- 마이그레이션 082는 주간 설정 컬럼만 추가한다. 이전 API는 추가 컬럼을 무시하며 기존 선택·풀이 데이터는 보존된다.
- 로컬 340개 어휘에서 랜덤 20개 조회를 EXPLAIN ANALYZE로 확인: 0.791ms (단일 로컬 측정, 네트워크 제외). 대규모 데이터의 성능 보장은 아니다.
- 관련 API 통합 테스트 14개, 빌드·ESLint 통과. 현재 세션에는 Chrome MCP가 없어 실제 브라우저 네트워크·콘솔은 미검증이다.
