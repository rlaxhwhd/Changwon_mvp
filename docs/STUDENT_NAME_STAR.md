# 학생 이름의 STAR 표시

2026-09-22: STAR 트랙 학생은 이름 바로 뒤에 `⭐`를 표시한다. 표 컬럼은 추가하지 않는다.

- 공통 표시 함수: `shared/studentDisplayName.ts`.
- 판정 정본: `dc.star_track` 소속 여부. 학년, 진단 유형, 이름 문자열로 추측하지 않는다.
- 학사/서비스 로스터와 학사 상세 API는 기존 조회 결과의 `star` 값을 반환한다.
- 기존 부팅 응답에 권한 범위 내 STAR 학생의 ID·별칭·학번만 추가한다. 학생별 상세 호출을 추가하지 않는다. 학생 본인은 본인만, 상담사는 전체, 다른 교직원은 기존 학생 범위, 전체학생 조회 권한자와 시스템관리자는 관리 범위의 표시용 식별자를 받는다. 상세 프로필 조회 권한은 그대로다.
- 화면 표시만 변경한다. DB 이름, 입력 폼의 이름 원본, 검색 조건, CSV/XLSX의 원본 이름은 그대로 사용한다.
- 학생관리·검색·상세 모달, 상담 접수·일정·기록·일지·인쇄, 검사현황·심리검사, 로드맵, 비교과 명단·블랙리스트, SMS 블랙리스트, 채용 지원자, 교수·조교 화면, 학생 포털의 이름 표시에 적용했다.

## 검증

- TypeScript 및 Docker api/web 빌드 성공.
- 학사 학생·STAR 식별자 권한 범위·역할별 부팅·시스템관리 권한 관련 테스트 22건 통과.
- Chrome: STAR 필터 학생 1명에 별 표시, 학생 상세 모달 표시, 상담일지의 STAR 행 3건/일반 행 4건 구분 및 수정 모달 표시, 상담기록·검사현황 표시 확인.
- 실제 STAR 테스트 학생으로 로그인해 `/v2/lounge` 이름의 별 표시 확인 후 테스트 세션 로그아웃.
- 전체학생 표는 기존 8열 유지. 확인 화면의 가로 넘침·콘솔 오류·실패 API 없음. 이름 표시만을 위한 STAR 상세 요청 0건. 부팅 프로필 요청 200, 약 329ms.
- 부팅 회귀 테스트의 고정 Idempotency-Key를 실행별 고유 키로 변경해 재실행 시 충돌을 제거했다.
- 별도로 실행한 시스템관리 전체 테스트는 재사용 테스트 DB의 기존 이벤트·등록 데이터가 누적되어 재실행 시 4건이 실패했다. 최종 22건은 해당 데이터 생성 테스트를 제외한 관련 검증 범위이며 전체 회귀 통과를 의미하지 않는다.
