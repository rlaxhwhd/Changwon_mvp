# 교수 상담관리

2026-10-20 사용자 확정 사항을 반영한다.

- 상담관리 하위 순서: 신청접수 → 오프라인 상담현황 → 온라인 상담현황 → 상담실적 → 상담 설정.
- 기존 `/admin/professor/profile`, `/admin/professor/schedule` 페이지는 상담 설정(`/admin/professor/counsel/settings`)으로 통합한다. 옛 주소는 새 화면으로 이동한다.
- 현황은 해당 교수에게 배정된 확정·완료 상담만 채널별로 조회한다. 미접수 신청은 신청접수에서 처리한다. 검색·분류·상태·대학·학과·상담일 필터는 서버 페이지네이션 전에 적용한다.
- 미예약 상담은 기존 `counsel_request(DONE)`와 `counsel_record`를 한 트랜잭션으로 만든다. 학생 이름/제목은 인적사항·상담내용 수정 화면으로 연결된다. 확정된 신청의 기록 저장은 기존 완료 전이를 재사용한다.
- **온라인 상담내용은 학생 공개 답변이다.** 저장 시 `counsel_record.comment`에도 반영한다. 오프라인 내용은 내부 기록으로만 저장한다. 기존 기록을 새로 저장하기 전 일괄 공개하지 않는다.
- 제목은 신청의 `source_payload.reportTitle`, 상담일·시작/종료·장소는 기존 신청 컬럼을 사용한다. 수정은 신청·기록 버전을 검사하고 변경 전후 이벤트를 남긴다.
- 첨부파일은 기존 검증·비공개 파일 저장소의 `COUNSEL_REQUEST/COUNSEL_ATTACHMENT`를 사용한다. 파일당 10MB, 상담당 최대 10개이며 담당 교수만 접근한다.
- **교수상담은 실제 삭제한다.** 해당 교수만 버전을 확인하여 신청·상담기록·상담이벤트·연관 알림/읽음·관련 중복요청 응답·첨부 메타/본문을 삭제할 수 있다. API 역할에는 일반 DELETE 권한을 주지 않으며, 검증하는 DB 함수로만 실행한다. 다른 상담의 이벤트·알림은 계속 변경/삭제를 차단한다. 다른 업무에서 참조하는 상담은 무결성 제약에 따라 삭제를 거절한다.
- 상담실적은 해당 교수의 완료 기록을 상담일·분류·온라인/오프라인 기준으로 집계한다. 영구 삭제한 건은 제외된다. 이미 부여된 별도 퀘스트 보상 등 다른 도메인의 이력을 소급 취소하는 기능은 포함하지 않는다.

## 마이그레이션과 복구

134는 메뉴 이동, 135는 첨부 용도 확장, 136·137은 교수상담 삭제 및 해당 알림의 삭제 예외다. 기존 적용 파일은 변경하지 않는다.

로컬은 `npm run docker:up`으로 이미지 빌드 → DB 백업 → 마이그레이션 → 서비스 기동 순서로 반영한다. 운영 반영은 별도이며 환경별 비밀과 업무 데이터를 유지한다.

코드 복구 시 이전 버전으로 되돌린 뒤 새 보정 마이그레이션으로 메뉴를 복원하고 교수 삭제 함수를 비활성화한다. 실제 삭제된 상담은 DB 및 파일 백업 없이는 복원할 수 없다. 첨부 참조가 남은 상태에서 확장된 파일 제약을 축소하지 않는다.

## 검증

격리 DB에서 목록·기간/검색·온라인 답변·수정 버전·소유권·확정 상담 완료·첨부 권한·실제 삭제·다른 상담 이력 보존·메뉴 순서 검사를 포함한 관련 17개 테스트를 통과했다.

확장 회귀는 118개 통과, `test_development_roadmap.py::test_staff_requires_both_menu_and_student_scope` 1개 실패다. 이 실패는 변경 전 `15f0c55`의 별도 체크아웃에서도 같은 조건으로 재현했다(예상 403, 실제 200). 교수상담 변경의 회귀 통과와 전체 회귀 통과를 구분한다.

Chrome MCP의 격리 DB 화면에서 오프라인 등록·상세 수정, 온라인 등록·학생 답변 조회, 삭제·집계 제외를 확인했다. 검증용 상담은 로컬 업무 DB나 운영 DB에 생성하지 않았다.

로컬 DB 백업 후 134~137 적용, 최신 API·웹 Docker 빌드와 기동을 완료했다. 로컬 Docker 실제 화면에서 오프라인 목록/옵션 요청은 각각 1회, 200/45ms/50B 및 200/36ms/20B였고(현재 해당 교수 조회 결과 0건), 콘솔 오류·가로 넘침이 없었다. `/professor/profile`, `/professor/schedule`은 통합 설정으로 이동하며 설정에 노출·제한일정이 함께 표시된다. 개발 서버의 초기 조회 중복과 배포용 Docker의 단일 조회를 구분한다. CentOS에는 이번 변경을 배포하지 않았다.
