현재 서버는 API/web deep-20261116 및 마이그레이션 164까지 적용됐고 DeepResume 설정은 사용자 승인에 따라 활성화돼 있다. 대상 커밋에 대해 승인 기록을 찾지 못해 DB 적용 전에 Astra 검토를 요청한다. 이 지시는 신규 구현이 아니라 이미 커밋된 동의서 저장/조회/세션 스냅샷/프런트 계약의 배포 안전성 검토이다.

학생·동의서 버전별 불변 동의 기록을 새 테이블에 보관하고 기존 세션 중 가장 이른 동의를 백필한다. 같은 버전의 재동의는 원래 기록을 유지하며 새 버전은 새 동의가 필요하다. 면접 세션에는 근거 동의의 값과 동의 시각을 복사한다. 다른 업무 규칙이나 외부 계약은 변경하지 않는다.

검토 대상: FK/복합 PK/JSON 및 길이 제약, UPDATE 차단/DELETE 권한, 원래 세션 보존 및 백필 선택의 결정성, 실제 조회 인덱스, 동시 재동의 멱등성, 본인/학생 권한, 동의 버전·응답 검증, Deep HTTP 전에 커넥션 반환, 현재 버전 상태 응답과 프런트 단계 생략, 롤백 및 테스트 범위.

검토 승인 전 DB에 적용하지 않는다. 승인 후 깨끗한 커밋 소스의 격리 회귀 테스트 → 로컬 Docker → 로컬 코드/165 마이그레이션/스키마 감사 → 서버 백업 복원 DB 적용 및 데이터 보존 비교 → 운영 직전/직후 비교 → API·웹 교체 → 실제 조회 화면/API 확인 순서로 진행한다. 운영 학생의 동의를 대리 작성하거나 실제 외부 면접을 시작하지 않는다. 이전 API/web 복구 시 새 동의 및 세션 기록은 보존한다.
